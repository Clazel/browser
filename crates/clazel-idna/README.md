# clazel-idna

Punycode and UTS #46 internationalised domain name processing, formally
verified with Verus. Part of [Clazel](../../README.md), a web browser built
from the bottom up by AI using formal verification instead of trust.

## What it is

Two parts:

- `punycode`: RFC 3492 Punycode, decoding (section 6.2) and encoding
  (section 6.3), with the bias adaptation of section 6.1 and the overflow
  handling of section 6.4.
- `uts46`: Unicode IDNA Compatibility Processing (UTS #46, Unicode 18.0.0)
  section 4 processing, section 4.1 validity criteria, section 4.2 ToASCII
  and section 4.3 ToUnicode, with Normalization Form C from the Unicode
  Standard (sections 3.11 and 3.12), the ContextJ rules of RFC 5892 and the
  Bidi rule of RFC 5893. On top of these sit the WHATWG URL Standard
  section 3.3 "domain parser", "domain parser ToASCII" and "domain to
  Unicode".

Strings are sequences of code points held as `u32`. Not included:
Transitional_Processing and IgnoreInvalidPunycode (both fixed to false, the
only values the URL Standard uses), and Punycode's mixed-case annotation
(RFC 3492 Appendix A).

## Verification

Tier 2: the implementation is proven functionally correct against an
executable specification, with Verus. Verus also proves that it never
panics, overflows or indexes out of bounds. See the
[tiers](../../docs/VERIFICATION.md#tiers).

- Punycode `decode` and `encode` are proven against the RFC's pseudocode.
  Decoding inverts encoding whenever `35 * (c + 1) * (length + 1)` stays
  within the 32-bit `maxint` for the largest code point `c`, which covers
  any string of up to 100 scalar values. Outside that bound the round trip
  is not proven.
- The UTS #46 functions are proven against the spec **relative to the
  Unicode tables** in `src/uts46/data.rs`. The tables are generated by
  `cargo xtask tables` from vendored Unicode 18.0.0 data files (SHA-256s in
  `data/unicode-18.0.0/SOURCE.md`), and `cargo xtask check` fails if they
  differ. The proofs do not show that the tables equal the Unicode data.
- Independent transcriptions are proven equal to the spec on every input:
  Punycode from the RFC's Appendix C sample code, and in `uts46`, the Bidi
  rule, ContextJ, validity criteria 5 and 7, D115, D117 R1 and the Hangul
  sample code. The mapping, break and convert pipeline and the table-driven
  decomposition and composition have no second transcription, because no
  other document defines them; their evidence is the conformance tests.
- Every mutation listed in `mutations.json` is certified as caught by a proof
  that Verus checks. The decoder's `w` overflow check is redundant under
  Punycode's parameters (`i` always overflows first), so it has no mutation.
- Conformance: the RFC 3492 section 7.1 samples, every row of WPT
  `url/resources/IdnaTestV2.json` and `toascii.json` (no expected failures),
  and differential tests against rust-url's `idna` 1.1.0 for Punycode and for
  random domains. `idna` predates two URL Standard rules, which the
  test documents.

Current proof, mutation and conformance counts are in the
[status table](../../README.md#verification-status).

## Trust

The proofs assume the Rust compiler, Verus, the generated Unicode tables
(checked against the data files by regeneration, not proven), and that the
spec matches the standards, which the conformance tests and the independent
transcriptions support but cannot prove. See the
[trusted computing base](../../docs/VERIFICATION.md#trusted-computing-base-what-we-do-not-prove).

## Usage

Not yet published to crates.io (the workspace sets `publish = false`, and
the version is `0.0.0`). Use it as a path dependency:

```toml
[dependencies]
clazel-idna = { path = "crates/clazel-idna" }
```

```rust
use clazel_idna::{
    punycode,
    uts46::process::{domain_parser, domain_to_unicode},
};

fn u(s: &str) -> Vec<u32> {
    s.chars().map(|c| c as u32).collect()
}
fn s(v: &[u32]) -> String {
    v.iter().filter_map(|&c| char::from_u32(c)).collect()
}

fn main() {
    // URL Standard "domain parser" (be_strict = false), as the host parser uses it.
    let ascii = domain_parser(&u("Bücher.Example"), false).unwrap();
    assert_eq!(s(&ascii), "xn--bcher-kva.example");
    assert!(domain_parser(&u("a b"), false).is_none()); // forbidden domain code point

    assert_eq!(s(&domain_to_unicode(&u("xn--bcher-kva.example"))), "bücher.example");

    // Punycode alone; `None` is failure.
    assert_eq!(s(&punycode::encode::encode(&u("bücher")).unwrap()), "bcher-kva");
    assert_eq!(s(&punycode::decode::decode(&u("bcher-kva")).unwrap()), "bücher");
}
```

`uts46::process::to_ascii` and `to_unicode` expose the UTS #46 algorithms
with their flags (`uts46::spec::Flags`).
