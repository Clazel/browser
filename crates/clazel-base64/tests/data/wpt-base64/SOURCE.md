# WPT `fetch/data-urls/resources/base64.json`, forgiving-base64 decode cases

Commit: 4ad507b28db0a636f528def9161d109fe11b93a3

`base64.json` is copied byte for byte from `fetch/data-urls/resources/` at
that commit (the same WPT commit as `clazel-encoding`'s suite); `LICENSE.md`
from the repository root. To update, copy the file from a newer commit,
change the commit above, and run `cargo xtask testdata`.

`xtask/src/testdata/wpt_base64.rs` converts it into
`tests/generated/wpt_base64.rs`, read by `tests/conformance_base64.rs`.
All 80 rows are converted.

How the rows map onto Infra: WPT's `fetch/data-urls/base64.any.js` fetches
`data:;base64,<input>` and expects the bytes, or a `TypeError` for `null`.
The data: URL processor runs forgiving-base64 decode on the URL's body, so
each row is a decode case once the URL layer is accounted for. The
converter passes the input to decode directly, and refuses any row where
the URL layer could change the result (a `%` or `#`, or a non-whitespace C0
control at the very end); the reasons are in the converter's
`check_direct`. No current row is refused.

Not converted: `html/webappapis/atob/base64.any.js`, which tests `atob()` and
`btoa()`. Those add WebIDL string conversion and `btoa`'s Latin-1 check on
top of forgiving base64, and the file's cases are generated by JavaScript
code, not data. The encoder is covered by the differential test and the
round trip in `conformance_base64.rs`.
